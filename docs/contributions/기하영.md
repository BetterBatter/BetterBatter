**2. [BLOCKCHAIN] 서비스 내 블록체인 적용 방안 조사**

- **세부 내용**
  - Prediction 서비스에서 블록체인이 필요한 부분과 일반 서버에서 처리할 부분 검토
  - 모든 응답과 포인트 변화를 블록체인에 기록하면 처리 속도와 가스비 문제가 발생할 수 있음을 확인
  - 실시간 경기 데이터, 질문 추천, 응답 저장, 포인트 계산은 오프체인에서 처리하는 구조 검토
  - 최종 경기 결과와 참여·정산 기록의 해시값은 온체인에 남겨 기록을 검증하는 방식 조사
  - 여러 사용자의 응답을 Merkle Tree로 묶고 Merkle Root만 저장하는 방식 검토
  - Oracle을 통해 경기 결과를 Smart Contract에 전달하는 흐름 조사
  - Wallet은 포인트 보관보다 사용자 응답 서명과 기록 검증에 활용하는 방향 검토
- **성과 및 결과**
  - 블록체인을 실시간 처리 수단이 아닌 결과 및 정산 기록의 검증 수단으로 사용하는 방향 정리
  - 온체인과 오프체인의 역할을 분리하여 가스비와 처리 속도 문제를 줄일 수 있는 구조 제안

**3. [추천] 빅데이터 기반 질문 추천 방식 구체화**

- **세부 내용**
  - 성공 확률뿐 아니라 현재 이닝, 다음 타순, 최근 경기력, 상대 전적 등 경기 상황을 반영하는 방식 제안
  - 선수의 특징, 질문의 흥미도, 질문 유효성, 선수 교체 가능성 등을 추천 기준 후보로 정리
  - 상대 전적이 부족한 경우 선수별 기록과 구종·좌우 상대 성적을 이용해 Matchup Score를 계산하는 방식 검토
  - 선수 교체에 대비하여 여러 질문 후보를 미리 만들고, 교체 감지 후 후보를 다시 정렬하는 구조 검토
  - 사용할 수 있는 선수 질문이 없을 때 이닝 득점·안타 여부와 같은 예비 질문을 사용하는 방안 제안
- **성과 및 결과**
  - 질문 추천 기준을 단순 확률 중심에서 경기 상황과 흥미도 중심으로 구체화
  - `후보 생성 → 선수 교체 확인 → 유효성 검사 → 재정렬 → 예비 질문 선택` 흐름 정리
  - 직접 상대 전적이 없거나 선수가 교체되는 상황에서도 질문을 추천할 수 있는 방안 마련

**4. [추천] 추천 시스템의 추가 활용 방안 검토**

- **세부 내용**
  - Prediction 질문 외에 추천 기술을 적용할 수 있는 서비스 기능 검토
  - 사용자가 선호하는 선수와 타격 유형, 장타력, 출루율, 도루 성향 등이 비슷한 선수 추천 방안 제안
  - 사용자의 Prediction 참여 기록을 이용해 관심 선수와 플레이 유형을 파악하는 방식 검토
  - 선호 팀, 선수 및 구매 이력을 활용한 응원 아이템·프로필 아이템 추천 방안 검토
- **성과 및 결과**
  - 추천 시스템의 활용 범위를 질문 추천, 유사 선수 추천, 사용자 취향 기반 추천, 상점 아이템 추천으로 정리
  - 향후 서비스 개인화 기능에 추천 기술을 활용할 수 있는 방향 제안

**5. [DATA] MLB API 기반 질문 목록 작성**

- **세부 내용**
  - MLB Stats API의 경기 상태와 Play-by-Play 데이터에서 결과를 확인할 수 있는 항목 조사
  - 추천된 질문의 결과를 API 데이터로 명확하게 판정할 수 있는지 검토
  - 안타, 출루, 장타, 홈런, 삼진, 볼넷, 도루, 득점 여부를 질문 유형으로 정리
  - 특정 선수의 타석 결과, 특정 이닝의 팀 득점 여부 등 선수·팀 단위 질문 검토
  - 선수 과거 기록과 실시간 경기 상황을 함께 사용해 질문 후보를 만드는 방식 검토
- **성과 및 결과**
  - MLB API 데이터로 출제하고 정산할 수 있는 기본 질문 목록 작성
  - 질문 생성 시 결과 판정 가능 여부를 확인하기 위한 기준 정리

### 이슈 및 위험 요인 (Issues & Blockers)

> 업무 진행 중 확인한 문제점과 대응 방향입니다.

- **[이슈 1] 선수 교체로 인한 질문 무효화 가능성**
  - 특정 선수를 대상으로 한 질문은 대타·대주자·투수 교체로 사용할 수 없게 될 수 있음
  - **대응 방안:** 여러 질문 후보를 미리 생성하고, 선수 교체 시 유효한 후보를 다시 정렬하여 선택
- **[이슈 2] 상대 전적이 부족한 타자·투수 조합**
  - 처음 만나는 선수는 직접 상대 전적만으로 질문을 추천하기 어려움
  - **대응 방안:** 선수별 기록과 구종·좌우 상대 성적을 이용한 Matchup Score 설계
- **[이슈 3] 실시간 질문 생성 시간 검증 필요**
  - 공수 교대 시간 안에 데이터 반영, 질문 선택, 배포가 가능한지 실측하지 못함
  - **대응 방안:** 다음 질문 후보를 미리 계산하고, 공수 교대 시 최신 상태 확인과 재정렬만 수행하는 방식으로 PoC 진행
- **[이슈 4] 블록체인 처리 범위에 따른 비용 문제**
  - 사용자 응답과 포인트를 모두 온체인에서 처리하면 가스비와 처리 속도 문제가 발생할 수 있음
  - **대응 방안:** 실시간 처리는 오프체인에서 수행하고, 참여·정산 기록의 해시값만 온체인에 저장
